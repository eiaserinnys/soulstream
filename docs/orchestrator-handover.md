# 오케스트레이터 넘기기

마이그레이션이 없는 배포에서 양쪽 릴리스가 겹침 기동을 선언하면 새 orch가 주인 잠금을 얻고 같은 포트에 리슨한다. 옛 orch는 새 리슨을 확인한 뒤 기존 연결을 정리하고 끝난다. 페이지 문서는 별도 잠금으로 저장을 마친 다음 넘긴다.

서버에 `net.ipv4.tcp_migrate_req=1`이 필요하다. 이 설정은 옛 리슨 소켓을 닫을 때 accept 대기열의 연결을 같은 포트의 새 리슨 소켓으로 옮긴다. 설정 적용은 배포 담당이 한다.

## 배경 정지 예산

정상 넘김은 `stop_background`에 60초 예산(`stopBudgetMs` 생성자 옵션)을 둔다. 예산을 넘기면 넘김을 취소하지 않고 `stop_background_over_budget`을 경과와 지금 도는 단계 이름(`current_step`)으로 남긴 뒤, 새 쓰기를 막고(fence) 소유권을 내놓고 넘김을 이어 간다. fence는 카드 디스패처에 새 일을 받지 않는 표시만 세우고 대기 중인 일은 기다리지 않으며, 외부 이벤트 저장소와 실패 저장소의 쓰기를 멈추고 그 둘을 기다린다. 끝나지 않은 정지는 계속 돌며, 넘김이 취소되면 그 정지가 끝난 뒤에 배경을 다시 시작한다.

넘김 성공 뒤 종료 길은 아직 도는 정지를 5초까지만 기다리고, 넘으면 로그만 남기고 다음 종료 단계로 간다.

`stop_background`의 단계마다 `orchestrator stop background step` 로그에 단계 이름과 `elapsed_ms`를 남긴다. 어느 단계가 늘어졌는지는 이 로그로 확인한다.
