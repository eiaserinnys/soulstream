# 무설치 노드 릴리스 묶음

> 범위 주석: 플랫폼 무관 payload를 만드는 빌드·pack 경로와, 노드에서 payload를 검증하고 `ReleaseManifestV1`을 쓰는 bind 경로만 다룬다. 배포 연결(eiaserinnys `post_pull`, orch `current` 응답, 판 전환)은 P7의 몫이며 이 지도에 없다.

> 경계 주석: 기존 `pnpm run build`(`dist/` + `dist/release-manifest.json` + `verify:bundle`)와 기존 기동 검증(`main.ts` → `release_runtime.ts` → `release_manifest.ts`)은 이 경로 때문에 바뀌지 않는다. payload는 별도 출력(`dist-portable/`)에서 만들고, 노드가 스스로 manifest를 쓰기 전에는 기동하지 않는다.

| 단계 | 파일:심볼 | 이 단계가 소유한 사실 | 거부/분기 조건 |
| --- | --- | --- | --- |
| 1. payload 빌드 | `soul-server-ts/tsup.portable.config.ts` (`build:portable`) | `main.js`, `runner/runner_release_prewarm.js`, `upstream/control_inbox_worker_entry.js`, `bind-release.mjs`, 청크를 `dist-portable/`에 만든다. `noExternal [/.*/]`와 `createRequire` 배너로 모든 npm 런타임 의존성을 인라인한다. | 출력 경로는 `dist/`가 아니다. `dist/`와 `deploy/release-manifest*.json`은 이 빌드가 건드리지 않는다. |
| 2. pack | `soul-server-ts/scripts/pack_portable_release.ts` (`pack:portable`) | `dist-portable/` 전체 + `dist/runner/{package.json,runner_entry.js}` + 루트 `package.json`(`type: module`)을 모아 `<out>/<source_commit>/node.tar.gz`와 `.sha256`을 만든다. `portable-release.json`에 schema/wire generation과 전달 파일 전부의 `path`·`sha256`·`size`를 나열한다. | `dist-portable` 또는 `dist/runner` 산출물이 없으면 실패. pack은 자기 출력을 노드와 같은 검증기(`verifyPortableReleasePayload`)로 다시 확인한 뒤 tar를 만든다. |
| 3. 메타데이터 | `soul-server-ts/src/release/portable_release.ts:parsePortableReleaseMetadata` | `schema_version: 1`, `source_commit`, `schema_generation`, `wire_generation`, `files[]`가 payload의 유일한 선언이다. 경로는 payload 루트 기준 POSIX 상대 경로만 허용한다. | 절대 경로·`..`·백슬래시·드라이브 경로·중복 경로·형식이 다른 digest/size는 거부한다. |
| 4. payload 검증 | `soul-server-ts/src/release/portable_release.ts:verifyPortableReleasePayload` | 나열된 모든 파일의 크기와 `sha256-<hex>`가 일치해야 하고, 런타임이 해시·import하는 파일(`HOST_RELEASE_ARTIFACTS`, `runner/{package.json,runner_entry.js}`, `bind-release.mjs`)이 목록에 있어야 한다. 노드 로컬 파일(`portable-release.json`, `release-manifest.json`, `.env.soul-server-ts`) 밖의 미선언 파일은 거부한다. | 하나라도 틀리면 bind하지 않는다. 검증 전에는 manifest를 쓰지 않는다. |
| 5. bind | `soul-server-ts/src/release/bind_release.ts:bindPortableRelease` / `bind-release_entry.ts` (`node <풀린 폴더>/bind-release.mjs --release-dir <dir> --env-file <file>`) | `source_commit`·`schema_generation`·`wire_generation`은 `portable-release.json`에서만 온다. 노드 Node 판·OS/arch·`deployment_env_identity`·Claude/Codex 실행 파일 identity는 이 노드와 env 문서에서 읽어 `ReleaseManifestV1`을 만들고 `<release-dir>/release-manifest.json`에 원자적으로 쓴다. | env 문서가 없으면 선언 없음으로 계산한다(서비스 기동과 같은 의미). 실행 파일 pin이 선언됐는데 파일이 없으면 실패. 실패는 exit 비-0 + `bind-release: <한 줄>` stderr. |
| 6. 기동 검증 | `soul-server-ts/src/main.ts` → `release_runtime.ts:loadAndVerifyReleaseManifest` | 기동 시 `dirname(main.js)/release-manifest.json`을 읽고 `HOST_RELEASE_ARTIFACTS` 해시, runner artifact 해시, schema/wire, 노드 identity, env identity, 실행 파일 identity를 다시 계산해 대조한다. | 중앙 빌드에서 복사한 manifest는 `host_bundle_hash`(필요하면 env·노드 identity)가 달라 거부된다. bind 뒤에만 통과한다. |
| 7. 러너 경로 | `runner/runner_release_prewarm.js`, `runner/runner_entry.js` | prewarm은 payload의 runner artifact로 release를 materialize하고 `runner_entry.js`는 `node_modules` 없이 자기 번들만으로 module graph를 완성한다. | Claude/Codex CLI는 payload 밖 호스트 실행 파일이다(`CLAUDE_CODE_EXECPATH`, `CODEX_CLI_PATH`). |
| 8. 시험 | `soul-server-ts/tests/release/portable_release.test.ts`, `soul-server-ts/scripts/verify_portable_release.test.mjs` (`verify:portable`) | vitest는 metadata 파싱·검증·bind·기동 검증·env drift를, node:test E2E는 pack→tar→깨끗한 임시 폴더 추출→중앙 manifest 거부→bind→`env -i` 기동 `/health`→runner prewarm/entry를 확인한다. | E2E는 `pnpm run build`와 `pnpm run build:portable` 산출물을 요구한다. |

이 장을 갱신해야 하는 변경 부류: `tsup.portable.config.ts` 진입·출력, `portable-release.json` 스키마, pack/bind CLI 계약, `HOST_RELEASE_ARTIFACTS`/runner artifact 구성, `ReleaseManifestV1` 축, 또는 노드 쪽 manifest 파일 위치 변경.
