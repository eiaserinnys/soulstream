# 무설치 노드 릴리스 묶음

> 범위 주석: 플랫폼 무관 payload를 만드는 빌드·pack 경로와, 노드에서 payload를 검증하고 `ReleaseManifestV1`을 쓰는 bind 경로만 다룬다. 배포 연결(eiaserinnys `post_pull`, orch `current` 응답, 판 전환)은 P7의 몫이며 이 지도에 없다. 판 파일은 배포 훅 `deploy/haniel/build-core.sh`가 빌드와 산출물 확인을 마친 뒤 `PORTABLE_NODE_RELEASES_DIR`가 설정된 호스트에서만 `deploy/haniel/pack_portable_node_release.sh`로 만들고, 이 스크립트는 배포 커밋의 깨끗한 공유 클론을 pack해 `<판 폴더>/<커밋>/`에 원자적으로 게시하며 최근 3개 커밋 폴더만 남긴다. pack이 실패하면 한 줄 경고만 남기고 배포는 성공으로 끝난다.

> 경계 주석: 기존 `pnpm run build`(`dist/` + `dist/release-manifest.json` + `verify:bundle`)와 기존 기동 검증(`main.ts` → `release_runtime.ts` → `release_manifest.ts`)은 이 경로 때문에 바뀌지 않는다. payload는 별도 출력(`dist-portable/`)에서 만들고, 노드가 스스로 manifest를 쓰기 전에는 기동하지 않는다.

| 단계 | 파일:심볼 | 이 단계가 소유한 사실 | 거부/분기 조건 |
| --- | --- | --- | --- |
| 1. payload 빌드 | `soul-server-ts/tsup.portable.config.ts` (`build:portable`) | `main.js`, `runner/runner_release_prewarm.js`, `upstream/control_inbox_worker_entry.js`, `bind-release.mjs`, 청크를 `dist-portable/`에 만든다. `noExternal [/.*/]`와 `createRequire` 배너로 모든 npm 런타임 의존성을 인라인한다. | 출력 경로는 `dist/`가 아니다. `dist/`와 `deploy/release-manifest*.json`은 이 빌드가 건드리지 않는다. |
| 2. pack | `soul-server-ts/scripts/pack_portable_release.ts` (`pack:portable`) + `src/release/portable_pack_source.ts`(깨끗한 트리·HEAD 게이트) | `dist-portable/` 전체 + `dist/runner/<RUNNER_RELEASE_ARTIFACTS>` + 루트 `package.json`(`type: module`)을 모아 `<out>/<source_commit>/node.tar.gz`와 `.sha256`을 만든다. `source_commit`은 pack이 확인한 `git HEAD` 하나뿐이다. 순서는 깨끗한 트리 확인 → `build` → `build:portable` → 다시 깨끗한 트리와 같은 HEAD 확인 → 포장이며, `portable-release.json`에 schema/wire generation과 전달 파일 전부의 `path`·`sha256`·`size`를 나열한다. | 작업 트리가 깨끗하지 않으면(`git status --porcelain` 비어 있지 않음) 빌드 전에 실패한다. 우회 플래그와 `--source-commit` override는 없다. 빌드 뒤 HEAD가 움직였거나 `dist-portable`/`dist/runner` 기대 파일이 없으면 실패. pack은 자기 출력을 노드와 같은 검증기(`verifyPortableReleasePayload`)로 다시 확인한 뒤 tar를 만든다. |
| 3. 메타데이터 | `soul-server-ts/src/release/portable_release.ts:parsePortableReleaseMetadata` | `schema_version: 1`, `source_commit`, `schema_generation`, `wire_generation`, `files[]`가 payload의 유일한 선언이다. 경로는 payload 루트 기준 POSIX 상대 경로만 허용한다. | 절대 경로·`..`·백슬래시·드라이브 경로·중복 경로·형식이 다른 digest/size는 거부한다. |
| 4. payload 검증 | `soul-server-ts/src/release/portable_release.ts:verifyPortableReleasePayload` | 나열된 모든 파일의 크기와 `sha256-<hex>`가 일치해야 하고, 런타임이 해시·import하는 파일(`HOST_RELEASE_ARTIFACTS`, `runner/<RUNNER_RELEASE_ARTIFACTS>`, `bind-release.mjs`)이 목록에 있어야 한다. 노드 로컬 파일(`portable-release.json`, `release-manifest.json`, `.env.soul-server-ts`) 밖의 미선언 파일은 거부한다. 열거와 읽기는 `lstat`으로 걷고, release-dir부터 각 파일까지의 부모 경로도 검사한다. | 하나라도 틀리면 bind하지 않는다. 검증 전에는 manifest를 쓰지 않는다. 심볼릭 링크와 일반 파일이 아닌 항목(디렉터리 제외), 링크를 지나는 경로 구성 요소는 payload 안팎을 가리지 않고 거부한다. |
| 5. bind | `soul-server-ts/src/release/bind_release.ts:bindPortableRelease` / `bind-release_entry.ts` (`node <풀린 폴더>/bind-release.mjs --release-dir <dir> --env-file <file> --catalog-path <clone>/packages/model-catalog/data/model-catalog.yaml`) | `source_commit`·`schema_generation`·`wire_generation`은 `portable-release.json`에서만 온다. `--catalog-path`가 있으면 그 경로를 manifest의 선택 키 `model_catalog_path`에 기록한다. 노드 Node 판·OS/arch·`deployment_env_identity`·Claude/Codex 실행 파일 identity는 이 노드와 env 문서에서 읽어 `ReleaseManifestV1`을 만들고 `<release-dir>/release-manifest.json`에 원자적으로 쓴다. | env 문서가 없으면 선언 없음으로 계산한다(서비스 기동과 같은 의미). 실행 파일 pin이 선언됐는데 파일이 없으면 실패. 실패는 exit 비-0 + `bind-release: <한 줄>` stderr. |
| 6. 기동 검증 | `soul-server-ts/src/main.ts` → `release_runtime.ts:loadAndVerifyReleaseManifest` | 기동 시 `dirname(main.js)/release-manifest.json`을 읽고 `HOST_RELEASE_ARTIFACTS` 해시, runner artifact 해시, schema/wire, 노드 identity, env identity, 실행 파일 identity를 다시 계산해 대조한다. | 중앙 빌드에서 복사한 manifest는 `host_bundle_hash`(필요하면 env·노드 identity)가 달라 거부된다. bind 뒤에만 통과한다. |
| 7. 러너 경로 | `runner/runner_release_prewarm.js`, `runner/runner_entry.js` | prewarm은 payload의 runner artifact로 release를 materialize하고 `runner_entry.js`는 `node_modules` 없이 자기 번들만으로 module graph를 완성한다. E2E는 추출한 payload의 `runner_entry.js --config`를 실제 호스트 소켓으로 몰아 claude/codex 엔진이 가짜 CLI(`CLAUDE_CODE_EXECPATH`, `CODEX_CLI_PATH`)를 띄우는 지점까지 간다. | Claude/Codex CLI는 payload 밖 호스트 실행 파일이다(`CLAUDE_CODE_EXECPATH`, `CODEX_CLI_PATH`). 실제 CLI·오케스트레이터가 필요한 턴 완주는 P7의 몫이다. |
| 8. 시험 | `soul-server-ts/tests/release/portable_release.test.ts`, `portable_pack_source.test.ts`, `soul-server-ts/scripts/verify_portable_release.test.mjs` (`verify:portable`) | vitest는 metadata 파싱·검증·bind·기동 검증·env drift·심볼릭 링크 거부·깨끗한 트리 게이트(임시 git 리포)를, node:test E2E는 pack(내부에서 build 수행)→tar→깨끗한 임시 폴더 추출→중앙 manifest 거부→bind→`env -i` 기동 `/health`→Bearer MCP initialize→runner prewarm/entry→엔진 spawn을 확인한다. runner 기대 목록은 `RUNNER_RELEASE_ARTIFACTS` 정본에서 읽는다. | E2E는 깨끗한 커밋에서만 돈다(pack이 더러운 트리를 거부한다). |

이 장을 갱신해야 하는 변경 부류: `tsup.portable.config.ts` 진입·출력, `portable-release.json` 스키마, pack/bind CLI 계약, `HOST_RELEASE_ARTIFACTS`/runner artifact 구성, `ReleaseManifestV1` 축, 또는 노드 쪽 manifest 파일 위치 변경.
